# 차곡 · 웹 목업

일상의 이동을 새로운 발견으로 바꾸고, 여행을 기록으로 남기는 차곡의 화면 데모입니다.
**이번 작업은 백엔드·실제 API 연결 없이 화면 구성과 클릭 흐름까지만 구현합니다.**

## 바로 실행

Node.js 설치 후 `phone` 저장소 루트에서 실행합니다. 별도 npm 설치는 없습니다.

```sh
node mockup/wireframe-server.cjs
```

http://127.0.0.1:4174/#phone=1&car=15&view=both 에서 차량과 폰을 함께 볼 수 있습니다.
이미 4174 포트를 사용 중이면 기존 목업 서버를 이용하거나 종료 후 실행합니다.

템플릿을 수정했다면 다음 명령 실행 후 브라우저를 새로고침합니다.

```sh
node mockup/redesign-wireframes.cjs
```

## 역할 분배

인원이 확정되기 전까지 두 작업 축으로 나눕니다. 이름은 팀에서 채워 주세요.

| 역할 | 담당 | 수정할 파일 | 완료 기준 |
|---|---|---|---|
| 차량 화면 | 팀원 A | `mockup/templates/car.html`, `mockup/templates/car-behavior.js` | 왼쪽 내비 고정, 중앙 구체, 대화·일정·발견·저장·마무리 흐름 |
| 폰 화면 | 팀원 B | `mockup/templates/phone.html` | 홈·여행 설정·추천·일정·사진 선택·기록 흐름, 한 화면의 정보량 줄이기 |
| 공통 화면·통합 | A/B 중 한 명 지정 | `mockup/dist/wireframe.html`, 서버·생성기, README | 폰·차량 함께 보기, 화면 선택, 화면 간 데모 상태 전달 |
| 확인 | 서로 교차 확인 | 상대 작업 화면 | 잘림·버튼·뒤로가기·새로고침·두 화면 연결 확인 |

2명이면 A/B로 나누고 한 명이 공통 파일을 맡습니다. 3명이면 공통 화면·통합·확인을 별도 담당으로 분리합니다. 다른 사람이 담당한 파일을 바꿀 때는 먼저 합의합니다.

## 이번에 만들 것

- 차량: 왼쪽 예시 내비를 유지하고 오른쪽에 파스텔 구체, 짧은 멘트, 응답 버튼 배치.
- 차량: 일정 상세, 주변 장소 한 곳씩 추천, 저장·경유지 승인 예시, 하루 마무리 질문.
- 폰: 여행 설정 → 샘플 장소 선택 → 일정 → 차로 보내기 데모.
- 기록: 샘플 사진 선택 → 여행 타임라인 → 요약.
- 폰과 차량 사이에는 같은 브라우저의 `postMessage`로 데모 상태만 전달.

**하지 않을 것:** 서버·DB·로그인 구축, 실제 AI·음성·지도·내비·차량 SDK 연결, 실제 사진·카메라·GPS 접근, 외부 메시지·알림 전송. 데이터는 샘플이며 새로고침하면 초기화됩니다. 음성처럼 보이는 구체는 애니메이션입니다.

## 파일 구조

```text
mockup/
  templates/car.html          차량 레이아웃·스타일
  templates/car-behavior.js   차량 5개 화면·버튼 동작
  templates/phone.html        폰 13개 화면·버튼 동작
  dist/wireframe.html         폰·차량 동시 보기와 공통 제어
  dist/wireframes/            생성된 화면 01~18 + manifest
  redesign-wireframes.cjs     템플릿 → 화면 생성
  wireframe-server.cjs        로컬 미리보기 서버
```

**실제 편집은 templates에서 합니다.** `dist/wireframes/01.html`~`18.html`은 직접 수정하지 않습니다. `dist/wireframe.html`은 예외로 직접 편집하는 공통 뷰어입니다.

## 협업 순서

1. 담당별 브랜치를 만듭니다: `feat/car-mockup`, `feat/phone-mockup`, 필요 시 `feat/preview-shell`.
2. 담당 템플릿을 수정하고 생성기를 실행해 화면을 확인합니다.
3. 템플릿과 함께 해당 생성 화면을 커밋합니다. 폰은 01~13, 차량은 14~18입니다.
4. PR에 바뀐 화면과 확인한 클릭 흐름, 화면 캡처를 적습니다.
5. 상대가 확인한 뒤 합칩니다. 생성 파일이 충돌하면 템플릿을 먼저 합치고 생성기를 다시 실행합니다.

공통 이벤트 이름은 임의로 바꾸지 않습니다: `chagok-ready`, `chagok-screen`, `chagok-car-screen`, `chagok-phone-screen`, `chagok-plan`, `chagok-place-saved`. 구체적인 메시지 구조는 현재 뷰어와 템플릿 구현을 기준으로 합니다. 브라우저 메시지의 origin/source 검사는 유지합니다.

## 완료 확인

- 폰에서 여행 설정 후 차로 보내면 차량의 목적지와 일정이 바뀐다.
- 차량 화면을 이동해도 왼쪽 예시 내비가 유지된다.
- 구체 애니메이션을 켜고 끌 수 있다.
- 장소 저장 → 승인/다음에 → 라디오 복귀가 동작한다.
- 폰 사진 선택 → 기록 → 요약이 이어진다.
- 폰만/차량만/함께 보기에서 레이아웃이 잘리지 않는다.
- 화면은 실제 연동 완료를 주장하지 않는다.

현재 소스·샘플 동작 검사와 로컬 HTTP 응답을 확인했습니다. 실제 브라우저 시각 검수는 팀에서 진행합니다.

웹 목업과 Android 앱(이 레포의 폰 앱, `pleos` 레포의 차량 앱)은 별도 구현이며 자동 동기화되지 않습니다.
